# OOMProtector (OOM Killer Guard)

**OOMProtector** защищает важные системные службы от завершения OOM-киллером при нехватке оперативной памяти. Скрипт находит установленные службы, настраивает для них `OOMScoreAdjust` через systemd drop-in и по умолчанию применяет защиту **без перезапуска процессов и разрыва клиентских соединений**.

Поддерживается обнаружение `x-ui`, `caddy`, `nginx`, `fail2ban` и `subpage-server`. При установке можно добавить собственные службы.

> **Важно:** OOMProtector снижает вероятность принудительного завершения защищённых процессов, но не увеличивает доступную память. Если RAM действительно закончится, OOM-киллер может завершить другие процессы.

## Установка

```bash
bash <(curl -Ls https://raw.githubusercontent.com/sngvy/OOMProtector/refs/heads/main/OOMProtector.sh)
```

Скрипту нужны права для изменения настроек systemd и параметров работающих процессов. При запуске он определяет доступные службы и предлагает настроить для них защиту.

По умолчанию используется `OOMScoreAdjust=-500`. Можно выбрать значение от `-1000` до `1000`, добавить службы и указать, применять ли настройки **сразу, без перезапуска**, или с перезапуском служб.

## Как работает защита

### Обнаружение служб

- Проверяет наличие `x-ui`, `caddy`, `nginx`, `fail2ban` и `subpage-server` через `systemctl cat`.
- Пропускает службы, которых нет в системе.
- Добавляет к обнаруженным службам те, которые вы указали вручную.

### OOMScoreAdjust

Для каждой найденной службы создаётся drop-in:

```text
/etc/systemd/system/<служба>.service.d/oom.conf
```

В нём задаётся `OOMScoreAdjust`, влияющий на приоритет процесса при выборе жертвы **OOM-киллером ядра**.

| Значение | Влияние на выбор процесса |
| --- | --- |
| `-1000` | Исключает процесс из выбора OOM-киллером ядра |
| `-500` | Защищает сильнее обычного процесса; значение по умолчанию |
| `0` | Нейтральная настройка |
| `1000` | Делает процесс максимально предпочтительной жертвой |

Чем **ниже** значение, тем **менее вероятно**, что ядро выберет процесс для завершения при нехватке памяти.

### Применение без перезапуска

По умолчанию OOMProtector изменяет `/proc/<pid>/oom_score_adj` у всех процессов службы, найденных в её cgroup. Это позволяет применить новое значение к уже работающим процессам **без остановки службы**.

Если немедленное применение не удалось, скрипт предупреждает, что настройка вступит в силу после перезапуска. При установке также можно сразу выбрать применение с перезапуском служб.

### Поддержка systemd-oomd

Если в системе работает `systemd-oomd`, OOMProtector дополнительно записывает в drop-in:

```ini
ManagedOOMPreference=omit
```

Это отдельная мера для `systemd-oomd`: в отличие от OOM-киллера ядра, он реагирует на давление памяти и **не руководствуется** `OOMScoreAdjust`. Защита с `ManagedOOMPreference=omit` зависит от особенностей работы и конфигурации `systemd-oomd`.

## Повторная установка и проверка

OOMProtector помечает созданные файлы строкой:

```text
# Managed by OOMProtector
```

При повторном запуске скрипт:

- Находит ранее созданные настройки по этой метке и позволяет сохранить текущие значения нажатием Enter.
- Не перезаписывает drop-in, если его содержимое не изменилось.
- Сохраняет обнаруженный пользовательский `oom.conf` **без метки** в `oom.conf.bak` перед изменениями.
- Сверяет итоговый параметр через `systemctl show` с фактическим значением в памяти работающих процессов.
- Предупреждает, если `OOMScoreAdjust` переопределён другим drop-in. При наличии нескольких drop-in порядок их применения имеет значение.

## Удаление защиты

В меню скрипта предусмотрено удаление установленной защиты. При этом он:

1. Удаляет **только свои** drop-in-файлы с меткой `# Managed by OOMProtector`.
2. Выполняет `systemctl daemon-reload`.
3. Возвращает работающим процессам значение, которое теперь задаётся настройками systemd, **без перезапуска служб**.

Пользовательские файлы без метки не удаляются.

## Ограничения

- **Защита не решает проблему нехватки памяти.** При исчерпании RAM ядру всё равно может понадобиться завершить другой процесс.
- **`OOMScoreAdjust` и `systemd-oomd` работают по разным механизмам.** Для последнего используется отдельная настройка `ManagedOOMPreference=omit`.
- **Проверяйте предупреждения о переопределении параметров.** Другие systemd drop-in могут изменить итоговое значение.
- **При постоянном дефиците RAM** стоит рассмотреть добавление `swap` или `zram`.
