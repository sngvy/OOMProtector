# OOMProtector (OOM Killer Guard)

**OOMProtector — это скрипт, который находит в системе важные службы (x-ui, caddy, nginx, fail2ban, subpage-server) и защищает их от убийства OOM-киллером ядра через systemd drop-in с `OOMScoreAdjust` — без перезапуска служб и разрыва соединений клиентов.**

# Использование

**`bash <(curl -Ls https://raw.githubusercontent.com/sngvy/OOMProtector/refs/heads/main/OOMProtector.sh)`**

# Технические детали

- **Обнаружение: службы `x-ui`, `caddy`, `nginx`, `fail2ban` и `subpage-server` ищутся через `systemctl cat`, отсутствующие в системе пропускаются. При установке можно указать дополнительные службы — они добавляются к списку.**
- **Защита: для каждой найденной службы создаётся `/etc/systemd/system/<служба>.service.d/oom.conf` с `OOMScoreAdjust` (по умолчанию `-500`, допустимо от `-1000` до `1000`). Чем меньше значение, тем реже OOM-киллер выбирает процесс; `-1000` полностью исключает его из выбора.**
- **Применение: по умолчанию значение записывается на лету в `/proc/<pid>/oom_score_adj` всех процессов службы (по её cgroup), поэтому перезапуск не нужен и соединения клиентов не рвутся. Если на лету применить не удалось, скрипт предупреждает, что значение вступит в силу после перезапуска. Альтернативно можно выбрать перезапуск служб.**
- **systemd-oomd: если он запущен, в drop-in дополнительно добавляется `ManagedOOMPreference=omit` — oomd убивает службы по давлению памяти и игнорирует `OOMScoreAdjust`.**
- **Повторный запуск: drop-in помечается строкой `# Managed by OOMProtector`, по ней скрипт находит прошлую установку и предлагает оставить текущие значения (Enter). Неизменившиеся файлы не переписываются; найденный вручную созданный `oom.conf` без метки сохраняется как `oom.conf.bak`.**
- **Проверка: после применения скрипт сверяет значение по конфигу (`systemctl show`) и фактическое в памяти процесса; если `OOMScoreAdjust` переопределяет другой drop-in (файлы читаются по алфавиту, поздний побеждает), выводится предупреждение.**
- **Удаление: пункт меню удаляет только файлы с меткой, делает `daemon-reload` и возвращает работающим службам значение, которое теперь задаёт systemd, — тоже без перезапуска. Файлы без метки не затрагиваются.**
- **Ограничения: защита снижает вероятность убийства службы, но не устраняет нехватку памяти — при реальном исчерпании ядро убьёт другой процесс, поэтому при нехватке RAM стоит добавить swap или zram.**
